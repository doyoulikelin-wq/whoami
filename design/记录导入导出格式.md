# WhoAmI 记录档案格式 v1

本格式用于保存记录副本、交给 AI 分析，以及将 JSON 档案合并回 WhoAmI。只包含已经保存的真实记录，不包含示例、未保存草稿、项目详情或复盘报告。Markdown 和 JSON 使用相同的记录集合与时间范围。

## 时间与导出范围

- 每条记录保留保存时的具体时间，格式为 ISO 8601，含毫秒和 UTC 偏移。例如 `2026-09-07T14:05:06.789+08:00`。
- 导出保留原来的时间点；显示偏移采用导出时选择范围所用的本地时区。档案顶层同时记录该时区的 IANA 标识，例如 `Asia/Shanghai`。
- 亚毫秒部分向下截断，避免 `23:59:59.9998` 被四舍五入到第二天。秒和毫秒不会被改为导出时间。
- “当天”和“指定日期”按本地时区当天 `00:00:00` 起、下一天 `00:00:00` 前筛选 `createdAt`。日界线由日历计算，兼容夏令时。
- “全部”包含全部已保存真实记录。记录按创建时间升序排列；时间相同则按 UUID 排序，保证稳定输出。
- 文件名为 `WhoAmI_日期或全部记录_导出年月日-时分秒.md` 或 `.json`。

## JSON

顶层字段固定如下。示意内容仅用于说明格式，不是用户记录。

```json
{
  "format": "whoami.records",
  "schemaVersion": 1,
  "exportedAt": "2026-09-07T16:00:00.000+08:00",
  "timeZone": "Asia/Shanghai",
  "scope": {
    "kind": "day",
    "date": "2026-09-07"
  },
  "recordCount": 1,
  "records": [
    {
      "id": "00000000-0000-0000-0000-000000000001",
      "title": "格式说明",
      "body": "（正文原文）",
      "createdAt": "2026-09-07T14:05:06.789+08:00",
      "updatedAt": "2026-09-07T14:05:06.789+08:00",
      "domain": { "key": "career", "name": "事业与创造" },
      "moodIntensity": 51,
      "moodBand": "平静",
      "legacyMood": null,
      "projectID": null
    }
  ]
}
```

| 字段 | 约定 |
| --- | --- |
| `format` | 必须是 `whoami.records`。 |
| `schemaVersion` | 当前仅支持整数 `1`。 |
| `exportedAt` | 此档案的生成时间，不代替记录时间。 |
| `timeZone` | 导出范围使用的时区标识。 |
| `scope.kind` | `all` 或 `day`。 |
| `scope.date` | `day` 时为 `yyyy-MM-dd`；`all` 时省略。 |
| `recordCount` | 必须与 `records` 数量一致。 |
| `records[].id` | 原记录 UUID；重复导入按此标识去重，不覆盖设备中同 ID 的记录。 |
| `title` / `body` | 保存的标题和正文；正文原样保留 Unicode、空格、换行和标点。 |
| `createdAt` | 原记录创建时间，含秒、毫秒和 UTC 偏移。 |
| `updatedAt` | 可为 `null`；存在时须为有效时间，且不早于 `createdAt`。 |
| `domain` | 稳定维度键与中文名称。旧记录未选择维度时为 `null`。 |
| `moodIntensity` | 整数 `1…99`，或 `null`。缺失的旧数据不会补成 50。 |
| `moodBand` | 随数值生成：`1…33` 淡漠、`34…66` 平静、`67…99` 冲动；无数值时为 `null`。 |
| `legacyMood` | 旧版心情键，可能为 `calm`、`happy`、`focused`、`tired`、`low` 或 `null`。保留历史信息，不替代心境数值。 |
| `projectID` | 旧记录关联项目的 UUID 或 `null`，仅保留引用，不导出项目详情。 |

七个稳定维度键：

| key | name |
| --- | --- |
| `career` | 事业与创造 |
| `finance` | 财务与资源 |
| `body` | 身体与精力 |
| `emotion` | 情绪与应对 |
| `learning` | 学习与认知 |
| `relationships` | 关系与边界 |
| `life` | 生活与自主 |

导入只接受本格式 JSON，文件上限为 20 MB。解析时先验证整个档案：版本、元数据、UUID、重复 ID、时间、日期范围、维度、心境及旧字段均有效后，才返回待合并记录。任何错误都不会造成“导入前半部分”的状态。文件内重复 UUID 视为格式错误；与设备已有记录相同的 UUID 在合并时跳过。导入的记录不会覆盖当前编辑草稿。

## Markdown

Markdown 是提供给人或 AI 阅读的固定文本结构，不作为导入格式。

```text
# WhoAmI 记录档案

- 格式：whoami.records.markdown
- 版本：1
- 导出时间：ISO 8601 时间
- 时区：时区标识
- 范围：日期或全部已保存记录
- 记录数：条数
- 心境区间：1–33 淡漠；34–66 平静；67–99 冲动；未记录表示缺少测量。

## 记录 001

- ID：原始 UUID
- 记录时间：ISO 8601 时间
- 更新时间：ISO 8601 时间或“未修改”
- 维度：中文名称（稳定键）或“未指定”
- 心境：数值 / 名称，或“未记录”
- 标题（JSON 字符串）：标题

### 正文

正文放在独立代码块中。
```

每条记录采用相同字段顺序。正文使用足够长的反引号围栏，长度大于原文中最长连续反引号，避免正文内已有 Markdown 代码块截断原文。正文不做概括、清洗或情绪推断；JSON 是恢复时使用的无损结构化副本。

## 分享与本地保存

生成文件后调用 iOS 系统分享面板，可使用“存储到‘文件’”，也可选择设备已安装并支持接收文件的微信等应用。文件首先生成在 App 的临时目录，不会自动上传。是否发送、发送到哪个应用，由用户在系统面板中选择。
